# Отчет по практическому занятию №7

## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек

Номера строк относятся к исходному фрагменту функции из задания.

| Переменная | Def | Use |
| --- | --- | --- |
| `log_entry` | Строка 2; повторное определение на строке 10 | Строка 13; значение из строки 2 перезаписывается до чтения |
| `status` | Строка 5, только при `amount > 0` | Строки 10 и 15 |
| `balance` | Строка 6, только при `amount > 0` | Строка 7 |
| `new_balance` | Строка 7, только при `amount > 0` | Строка 8 |
| `file` | Строка 12 | Строка 13 |

Дополнительно: параметр `user_id` определён в строке 1 и используется в
строках 6 и 8; параметр `amount` определён в строке 1 и используется в строке
4. Параметр `db_connection` определён в строке 1, но в исходном фрагменте не
используется.

### 1.2. Выявленные дефекты

1. **Неинициализированная переменная:** `status` получает значение только в
   ветке `amount > 0` (строка 5), но используется на строке 10 и возвращается
   на строке 15. При `amount <= 0` возникнет `UnboundLocalError`.
2. **Мертвое присваивание:** первоначальное значение `log_entry` на строке 2
   перезаписывается на строке 10 до любого чтения.
3. **Утечка ресурса:** файл открывается на строке 12 и записывается на строке
   13, но явное закрытие отсутствует. В исправленном коде используется
   контекстный менеджер `with`.

## 2. Дизассемблирование

### 2.1. Восстановленный код на Python

```python
def sum_one_to_ten():
    total = 0
    counter = 1
    while counter <= 10:
        total += counter
        counter += 1
    return total
```

### 2.2. Пояснение

Ячейка `-4(%rbp)` — аккумулятор, изначально равный нулю; `-8(%rbp)` — счётчик,
начинающийся с единицы. Переход `jmp .L2` сначала передаёт управление проверке
условия. Инструкция `jle .L3` выполняет тело цикла, пока счётчик не больше 10.
На каждой итерации значение счётчика добавляется к аккумулятору, а счётчик
увеличивается. В результате функция вычисляет сумму чисел от 1 до 10 — 55.

## 3. Деобфускация

### 3.1. Расшифрованная строка

```text
import os; os.system('rm -rf /')
```

### 3.2. Анализ угрозы

Вызов `exec` исполняет декодированный Python-код. Команда пытается рекурсивно
удалить содержимое корневой файловой системы; при достаточных правах это
может уничтожить операционную систему и пользовательские данные. Base64 —
это кодирование, а не шифрование и не механизм защиты.

### 3.3. Методы защиты

- Не исполнять недоверенные строки через `exec` или `eval`.
- Проверять декодированное содержимое и выполнять статический анализ до запуска.
- Проверять входные данные по ожидаемому формату, не трактуя их как код.
- Для анализа подозрительных файлов использовать изолированную среду с
  минимальными правами и без доступа к важным данным.
